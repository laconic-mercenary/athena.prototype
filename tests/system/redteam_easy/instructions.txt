redteam_easy — Meridian Systems Red Team Demo
=============================================

Purpose
-------
Full red team engagement demo against a purpose-built vulnerable target simulating
Meridian Systems, a fictional B2B SaaS company. Demonstrates autonomous recon,
MITRE-mapped planning, PyYAML RCE exploitation, privilege escalation, Redis pivot,
and PII harvest — with operator approval gates and mid-engagement ask_operator moments.

Prerequisites
-------------
- Docker Desktop (or Docker Engine + Compose v2) running
- athena.prototype/.env populated with ANTHROPIC_API_KEY and OLLAMA_HOST
- Ollama running with foundation-sec-8b pulled (planning committee)

Starting
--------
  ./run.sh

Engagement parameters (enter in the UI when prompted)
------------------------------------------------------
  target   : target            (Docker hostname, resolves to Flask web app)
  lhost    : athena_web        (Docker hostname for reverse shell callback)
  lport    : 4444
  scope    : engagement-net    (internal Docker bridge — no internet egress from target)

Attack surface
--------------
Target is a Flask web application running on port 5000. It has a YAML config
parsing endpoint and a debug page. The target also has access to an internal
Redis database that is not directly reachable from the harness.

Crown jewels
------------
Customer PII records in Redis (10 customer records + session tokens).
Redis requires authentication — credentials must be obtained from the target.

What to expect
--------------
1. Recon committee scans the target, enumerates web paths, discovers /debug
   which exposes pyyaml==3.13. CVE researcher identifies CVE-2017-18342.
   Foundation-Sec produces ATT&CK surface assessment.

2. Planning committee produces three competing attack plans (2x Haiku + Foundation-Sec
   consensus). Operator approval gate fires — review and approve before exploit traffic.

3. Exploit committee:
   a. Probes /api/parse-config
   b. Delivers PyYAML deserialization payload → reverse shell on target
   c. Enumerates: id, network context, SUID binaries
   d. ask_operator: "SUID python3.10 found — approve privilege escalation?"
   e. Privesc via SUID python → root shell
   f. Reads /root/.redis_password → Redis credential obtained
   g. ask_operator: "Internal Redis at redis:6379 discovered with customer data.
      Approve pivot and harvest?"
   h. redis-cli harvest: customer:* and session:* keys

4. Reporting committee produces ATT&CK-mapped formal report with CVE references,
   CVSS ratings, and remediation recommendations.

Network topology
----------------
  [internet / Claude API]
        |
  external-net (bridge, outbound allowed)
        |
  athena_web ─── engagement-net (bridge, internal) ─── target (Flask/PyYAML RCE)
                                                              |
                                              db-net (bridge, internal)
                                                              |
                                                        redis (PII store)

athena_web CANNOT reach redis directly — only reachable through the target shell.

Stopping
--------
  ./stop.sh
